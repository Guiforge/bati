# Audit: sharing, 2026-10-01

> Worktree `share`, 8 shots taken by hand on the emulator (seeded year of history plus one seeded
> outing, map tiles switched on): the recap header, the share screen for an outing and for a
> workout, the Android share sheet, the journal list and session page, the new-quest editor with
> import, a hero quest with its share button. The five personas of the protocol, run in parallel
> on the same shots. The trigger was a hero's report: the share button was hard to find, and an
> accepted map never showed in the journal's previews.

## Second round: bugs, performance, QA

Three reviewers in parallel on the finished change, then a senior audit of the uuid work. What
they found and what became of it:

| Finding | Outcome |
|---|---|
| `transactionOrFallback` was never atomic on a phone: Drizzle's expo driver sends COMMIT at the callback's first `await`. Every multi-row save (a session, boss damage, an oath, an import) was written row by row. | **Fixed at the root**, `db/client.ts`: the native `withTransactionAsync`, which waits for the callback. `setQuestExercises` goes through the same queue. `db-transaction.test.ts` holds it against Drizzle's real behaviour. |
| Device sync matched two different hero quests by title (an outing filed as a quest on each phone copies the same seed title). | **Fixed**: hero rows match by uuid (0066); the name only speaks for a row with no uuid, and the named side's uuid is adopted. |
| The picture could be captured before its map arrived, under a map credit. | **Fixed**: `TraceThumb` reports the map's state, Send waits for it, the credit only shows over a displayed map, and the share card's snapshot jumps the queue. |
| Map snapshots queued for rows already scrolled away; `exists` checks on every render; old-style pictures kept forever. | **Fixed** in `src/gps/mapThumb.ts`: released rows fetch nothing, the folder is read once, other versions are deleted. No size cap yet (`ponytail:`). |
| A run under 400 m drew an empty square once its ends were cut. | **Fixed**: it shares as a workout does, with its painting. The ends are now cut on every shared picture, map or not. |
| GPX did nothing when the phone has no share sheet; double taps sent twice; caches refilled from a rolled-back write. | **Fixed.** The GPX case has a test; the double-tap guard (a ref) and the invalidation after a rollback are code only. |
| A write from outside the queue that lands during an open transaction is rolled back with it. | **Kept**, written down in `db/client.ts`: rare (a rollback is a failed save), and the exclusive connection that avoids it needs every write inside a transaction to go through `tx`. |
