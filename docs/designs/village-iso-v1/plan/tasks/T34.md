# T34 : Le build de release passe, sans erreur et sans warning

Rôle : iso-qa (seul à lancer Gradle), puis iso-engineer pour les corrections. Dépend de : T06 (tout le code de la V1 est là).

## But
Demande de Guillaume (31/10, LOG) : vérifier que `npm run release` fonctionne, build sans erreur et sans warning.

**Ne jamais lancer `npm run release`.** Le script (scripts/release.sh) monte la version, commite, pose un tag et pousse : le tag déclenche .github/workflows/release.yml, qui publie sur GitHub Releases, dans notre dépôt F-Droid et sur Play. Il refuse d'ailleurs de tourner hors de `main` ou avec un arbre sale. On rejoue donc **ce que le tag ferait**, en local, sur la branche, sans rien publier.

## À faire
1. **Les gardes du script**, sans effet de bord : `node -e 'require("./app.config.js")()'` (la version et le versionCode d'app.json s'accordent) ; la logique de montée de version lue et vérifiée sur une copie dans le scratchpad, jamais sur le dépôt.
2. **Le job `verify` de release.yml** : `npx biome ci --error-on-warnings .`, `npx tsc --noEmit --project tsconfig.json`, `npm test -- --coverage` sous Node 24 (`nvm exec 24`), `npm run deadcode`, `npx expo-doctor`, la commande de licences de ci.yml, `scripts/check-release-migrations.sh` contre le dernier tag.
3. **Le job `build`, les deux saveurs** (`foss` et `play`), dans un worktree jetable hors du dépôt et jamais dans `android/` suivi : les mêmes étapes que release.yml (fichier `.env` de distribution, module Play retiré pour `foss`, outils de dev retirés, `npx expo prebuild --clean --platform android`, puis la tâche Gradle du workflow), signées avec une clé de debug et **pas** avec la clé de release. Gradle par `scripts/iso/team/heavy.sh --gradle`, puis `./gradlew --stop`.
4. **Les contrôles d'après build** de release.yml sur l'APK et l'AAB : liste des permissions, pas de Google Play Billing dans `foss`, pages de 16 Ko (`readelf -lW`, chaque `LOAD` à 0x4000 ou plus).
5. **Les warnings** : chaque warning de chaque étape est relevé dans le rapport, avec sa source. Comparé au même relevé sur `main` (même commande, autre worktree), pour séparer ce que la V1 ajoute de ce qui était déjà là.

## Fini quand
- Zéro erreur à toutes les étapes, dans les deux saveurs.
- Zéro warning venu de notre code (app, plugins, scripts, config Gradle générée par nos plugins) : corrigés à la source, jamais tus par un réglage plus lâche, une baseline élargie ou un `--no-warn`.
- Les warnings qui viennent des dépendances (Gradle, Kotlin, AGP, modules natifs) sont listés à part avec le paquet en cause, et la V1 n'en ajoute aucun par rapport à `main`. Les faire taire n'est pas dans cette tâche ; Guillaume décide lesquels suivre.
- Rapport `docs/designs/village-iso-v1/reports/T34.md` avec les deux relevés (branche et `main`) et les commandes exactes.
