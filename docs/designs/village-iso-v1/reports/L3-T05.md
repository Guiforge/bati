# L3-T05 Croissance au retour de séance

## Fait
- `VillageScene` : le signal `grown` existant (effet `playedFor`) remplit un état `croissance` quand `iso` est vrai, passé à `IsoVillage` ; la carte le rend par `onCroissanceFinie`, donc un `grown` ne joue qu'une fois. En mode iso le zoom du tableau (`focus`) est éteint (la caméra iso recadre elle-même) ; la carte de récompense est inchangée. Drapeau éteint : chemin identique.
- `IsoVillage` : `croissance` / `onCroissanceFinie`. La caméra va au premier bâtiment monté (`useCameraIso.vers`, 600 ms, bornée par `ramener`, instantanée en mouvement réduit), puis `IsoCroissance` pose par-dessus la carte l'ancien sprite (opacité 1 vers 0) et le nouveau (opacité 0 vers 1, ressort 0,9 vers 1 depuis l'ancrage au sol). Fin à 1,4 s : la couche est démontée, rien ne tourne ensuite. Ancien stade inconnu (niveau 0) : fondu depuis rien ; même stade : ressort seul.
- Mouvement réduit : aucune couche, nouveau sprite direct, caméra posée sans animation.
- `app/dev-iso.tsx` : bouton `iso-grandir` (mode Village), `router.setParams({ grown: "forge:2:N" })` avec N croissant : rejoue la forge de rough vers son stade réel.

## Tour 2
- Cause du fondu invisible : `iso-grandir` posait `forge:2:N` sans regarder le héros (rough sur rough, rang affiché qui monte). Maintenant `croissanceDemo` (`components/village/iso/croissanceDemo.ts`, pure, testée) lit les bâtiments du héros à l'appui : premier bâtiment construit dont le stade réel n'est pas son premier, ancien niveau = le plus haut niveau inférieur d'un stade plus bas, nouveau = niveau réel. Chaîne `code:ancien:nouveau:rejeu` ; `parseGrown` ne lit que les trois premières parties, donc le suffixe change la chaîne (rejeu) sans changer les rangs. Si tous les bâtiments sont à leur premier stade : fondu depuis rien (`code:0:niveau`) ; rien de construit : pas de rejeu.
- Mineur 2 : confirmé, le sprite réel (déjà au nouveau stade) était peint sous la couche ancienne. `IsoCarte` reçoit `masques` : le sprite réel des bâtiments montés est à opacité 0 tant que la couche joue (jamais avec mouvement réduit), réaffiché quand le parent lâche `croissance`. Test dédié.
- Tests : `npx jest iso- village-scene` 9 suites, 179 verts ; `heavy.sh npx tsc --noEmit` vert ; biome `--error-on-warnings` vert sur les fichiers touchés.
- Non vérifié : rendu sur appareil (qa à refilmer) ; un héros dont tous les bâtiments sont au premier stade ne verra qu'un fondu depuis rien.

## Tour 3
- Cause racine (lue dans le code, pas devinée) : le fondu et le ressort montaient avec la couche au même instant que le recadrage (`vers`, 600 ms) ; fondu de 450 ms et ressort ayant fini de bouger dans la même fenêtre, ils étaient noyés dans le zoom, et ce qui restait à l'image ensuite était le sprite réel. Les tests ne le voyaient pas : ils ne regardaient que « la couche est montée », pas quand. Le ressort était aussi trop discret (départ 0,9, surtension faible). Le masque atteint bien le sprite (`Maquette` → `Planche invisible`, test) ; la couche est posée par `pose()` dans le même calque que la carte, donc dans le repère de la caméra. Le sprite « visible dès la première image » vu par qa : un frame ou deux avant que `croissance` arrive dans `IsoVillage` (l'état est posé par l'effet de `VillageScene`, un rendu après le montage de la carte), non corrigé.
- Correction : le sprite réel est masqué dès le début ; la caméra bouge d'abord (`CROISSANCE_CAMERA_MS` = 500) ; la couche (fondu 400 ms, ressort 0,7 vers 1, amortissement 9, surtension d'environ 7 %, stabilisé en ~0,5 s) ne monte qu'après (`lance`), fin totale `CROISSANCE_MS` = 1500 ms.
- Test ajouté/modifié : pendant le recadrage, aucune couche et sprite réel à opacité 0 ; après 500 ms les couches sont là ; fin à 1500 ms, `onCroissanceFinie` une fois, couches démontées, sprite réel rendu.
- Résultats : `npx jest iso- village-scene` 9 suites, 179 verts ; `heavy.sh npx tsc --noEmit` sans erreur ; biome `--error-on-warnings` propre.
- Non vérifié : rendu sur appareil (qa à refilmer). Le héros de l'émulateur retombe sur le repli `campfire:0:1` : fondu depuis rien, sans ancien sprite à croiser ; seul le ressort d'échelle (0,7 vers 1) et le fondu d'entrée se voient pour lui.

## Tour 5
- Lu dans le code : la couche pose le même rectangle que la carte. `Maquette` met `Planche` à `pose(code, s)` ; `IsoCroissance` met un conteneur à ce même `pose()` (mêmes valeurs, aucun arrondi) et la `Planche` dedans à (0, 0, w, h), même `contentFit="contain"`. À l'échelle 1 (le ressort s'arrête exactement sur sa cible) les deux sont identiques ; le test le vérifie sur le feu de camp (rect 64 x 96 dp). Ce n'est donc pas un écart de rectangle.
- Seule différence de dessin : l'ombre de socle (`ombreSocleDe`). La carte la peint AU-DESSUS du sprite (`Maquette` : Planche puis `OmbreSocle`) ; la couche, posée au-dessus de tout, la recouvrait, puis elle réapparaissait au remplacement. Le feu de camp en a une (rect ~24 x 16 dp). Corrigé : la couche redessine `OmbreSocle` (exporté, `testID` surchargeable) au-dessus d'elle, pour les mêmes données ; le remplacement ne change plus rien de dessiné.
- Non prouvé : que cette ombre explique les 5 px (167 vs 172) mesurés par différence de pixels ; je ne peux pas le mesurer sans appareil. Si qa mesure encore un écart après cette correction, ce serait alors la mesure (seuil de différence sur des bords antialiasés d'un sprite partiellement couvert) ou le décodage de l'image à la taille de la vue, à regarder sur appareil. qa à refaire la mesure.
- Test ajouté : rectangle de la couche et de son image égaux à `pose()`, ombre de socle présente dans la couche. Jest `iso- village-scene` : 10 suites, 192 verts ; tsc via heavy.sh sans erreur ; biome `--error-on-warnings` propre.
