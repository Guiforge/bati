## Tour 2 (revue `reviews/L0-T10.md`, importants et mineurs)
- **Échec en vol** : `settle()` est dans un `finally` autour du pool de `candidates()`. Un `IncompleteRead`, un `OSError` ou un Ctrl-C libère la réservation et inscrit les `cost` déjà facturés (`responses` garde chaque soumission acceptée). La graine est calculée avant `reserve()`, pour qu'aucune ligne ne puisse échouer entre la réservation et le `try`.
- **Recharge en cours de V1** : dans `settle()`, si le solde lu dépasse le dernier solde gardé (`v1.balance`, ou `initial_credits` au premier lot), la recharge s'ajoute à `initial_credits` et se note dans `v1.topups`.
  - Sa taille se mesure contre le solde que le coût du lot aurait dû laisser (`précédent - cost`). Mesurée contre le seul solde précédent, la recharge cachait la dépense du lot : le test a montré un faux écart de 0,225 $ avant cette correction.
  - Seule une hausse compte : un solde en retard d'un lot (constaté au POC) n'est pas pris pour une recharge.
  - Le dernier solde lu reste dans `v1.balance` (posé aussi par `start-v1` désormais).
- **Runs concurrents** : `locked()` prend un `fcntl.flock` exclusif sur `budget.lock` (à côté de `budget.json`) autour de chaque lecture-modification-écriture (`start_v1`, `ack`, `reserve`, `settle`). `save_ledger()` écrit dans `budget.json.tmp` puis fait `os.replace`.
- **Mineurs** :
  - plafond refusé s'il n'est pas fini ou s'il est ≤ 0 (`math.isfinite`) ;
  - `n < 1` refusé ;
  - `RESERVE["image"]` passe à 0,10 $ ;
  - message de `guard_endpoint` : « the V1 runs on flux-2-pro-preview only, a model change is Guillaume's » ;
  - `ack` porte en docstring la règle d'équipe (le chef d'équipe seul, après le point d'étape), sans garde dans le code.
- **Test** : `test_budget.py` passe maintenant par le vrai `candidates()` (`forge_solid`, variante `w5g`).
  - `flux.generate` est remplacé par un faux qui facture comme BFL : le `cost` à la soumission, et la baisse du solde.
  - `L.WORK` est redirigé vers le dossier temporaire.
  - Cas nouveaux : échec en vol au 2e rendu ; recharge de 5000 crédits ; deux `reserve()` simultanées avec de la place pour une seule (`spent()` ralenti de 0,2 s pour ouvrir la fenêtre de course).
- **Contre-épreuve** : `locked` remplacé par `contextlib.nullcontext` (mutation en mémoire, rien d'écrit). Le test de concurrence échoue alors : `AssertionError: [{'label': 'race', 'amount': 0.3, 'probe': None}]`. Un seul thread a abouti, l'autre est tombé sur le fichier temporaire partagé. C'est donc bien le verrou qui fait passer le test.

## Douteux ou non fait
- La taille d'une recharge suppose que le lot qui l'encadre est déjà débité. Une recharge qui tomberait sur un solde en retard d'un lot fausserait la contre-vérification d'un lot : un faux écart signalé, jamais une dépense cachée, puisque `spent()` garde le plus grand. Non éprouvé sur une vraie recharge.
- Le marqueur V1 du tour 1 n'a pas de champ `balance` : au premier lot, `settle()` part de `initial_credits` (même valeur). `budget.lock` sera créé au premier `reserve()`.
- L'alerte part après le lot qui franchit la tranche : dépassement d'un lot au plus, environ 0,23 $ à 3 candidats.
- Les compteurs de sonde du POC (`probe_real` 1,74 $ sur 2 $) bloqueraient encore `forge_solid` en variante magenta `""` ou `legacy`. La V1 peint en `w5g`, non concernée.
- `ack` sans garde dans le code : la règle (chef d'équipe seul) reste une règle d'équipe.
- Aucun lot réel n'a tourné (rendu interdit) : le chemin `candidates()` est prouvé avec un faux `flux.generate`.
