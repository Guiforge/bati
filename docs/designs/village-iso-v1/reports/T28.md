# T28 : profondeur des villageois

**Cause.** Un pas d'une case sans rang valable est coupé au bord entre deux cases (`decouper`). Les deux moitiés ne partagent aucune case, mais `indiceSegment` prenait le rang de la suivante `AVANCE_MS` (120 ms) trop tôt : le villageois, encore dans la case d'avant, était dessiné du mauvais côté pendant 3 à 4 images.

**Changement.** `components/village/iso/marcheurs.ts` : `Segment.net?: true` posé sur les moitiés qui commencent à un indice non entier ; `indiceSegment` ne les avance pas. Aucun rendu par image, aucun nœud animé.

**Test.** `__tests__/iso-marcheurs-profondeur.test.ts` : 30 i/s, palier 12, 3 jours x 25 vagues, rang du segment lu contre la case réelle (toutes les emprises, grandes comprises) ; bêtes (créneau fixe) ; ouvriers de chantier. Rouge avant (8 fautes en tête), vert après.

**Checks.** `npx jest iso- village-scene --testPathIgnorePatterns=/node_modules/` : 48 suites, 571 tests verts. `heavy.sh npx tsc --noEmit` : propre. `biome check --error-on-warnings` sur les 2 fichiers : propre.

**Limites.** Sur une coupe au bord, tout retard du rendu React reste visible 1 à 2 images (aucune règle de rang ne fait mieux). Film qa à 30 i/s encore à faire.

**Mesure ajoutée (revue).** Sans `net` (code d'avant), le test à retard nul trouve 488 images fautives sur 3 jours x 25 vagues (marcheurs et bêtes, palier 12) ; avec `net`, 0. Avec un retard de 50 ms sur le rang (réaction puis `scheduleOnRN`), la plus longue suite d'images fausses est de 2 au plus (test « with a 50 ms delay »), sans avance d'une image sur les `net`, donc non retenue.
