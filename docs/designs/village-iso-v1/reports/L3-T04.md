## Tour 3 (échecs de qa, L3-T07a)
1. **Défilement** : le verrou se pose dès le premier toucher sur la carte (`onBegin` du pan et du pincement), plus à l'activation, et se lève à `onFinalize` (fin, échec ou annulation) quand l'autre geste n'est pas actif. Pourquoi : le `ScrollView` natif franchit son seuil de glissé (≈ 8 dp) en même temps que le pan (`minDistance` 8) et gagne la course, d'où une page qui défile sous le doigt même lent ; avec `scrollEnabled` faux avant le premier mouvement, `ReactScrollView.onInterceptTouchEvent` ne prend jamais le geste sur Android et les touches arrivent au pan (RNGH). Compromis assumé : un glissé qui commence sur la carte ne fait plus défiler la page (elle défile par la liste en dessous) ; au cadrage la carte bouge peu, l'île remplit déjà la zone (double-tap ou pincement d'abord). Risque restant : `scrollEnabled` passe par `useAnimatedProps` (commit sur le fil UI, une à deux images) ; un flick très rapide pourrait encore passer. Si qa le voit, repli : `Gesture.Native()` sur le ScrollView avec `blocksExternalGesture`. Test : le verrou est vrai après `begin` seul et faux après `fail`.
2. **Tap bâtiment ouvrait le visionneur** : cause, le `onPress` du `YStack village-hero` voyait aussi le tap. Quand `iso` est vrai, le hero n'a plus ni `onPress`, ni rôle bouton, ni libellé « ouvrir la scène ». Test (`village-scene`) : appui sur le hero sans iso ouvre `village-scene-viewer` ; avec iso, `onPress` est absent et l'appui n'ouvre rien. Masque vérifié avec les vrais : `iso-camera` relit chaque sidecar (tous les stades de bâtiment, cellule par cellule) et compare à `opaque`, puis pour chaque bâtiment et stade un pixel plein donne le bâtiment et un pixel vide rien. Le masque n'est donc pas en cause.
3. **Accessibilité** : vues posées au rectangle du sprite dans la caméra (style testé : `left/top/width/height` = `pose(...)`, dans `iso-camera`, conteneur `iso-acces` de la taille de la carte), désormais `collapsable={false}`, `focusable`, `importantForAccessibility="yes"`, `pointerEvents="none"` chacune et `box-none` sur le conteneur (il était `none`). Action `activate` conservée (RN Android la mappe sur ACTION_CLICK). Limite : jest ne voit pas les bornes natives. Je n'ai pas établi pourquoi les bornes étaient plein écran ; ce sont ces changements qui sont mon hypothèse (vue aplatie ou conteneur `none`). `qa` : refaire le dump uiautomator ; si les bornes restent `[0,0][1080,2400]`, sortir les vues de la caméra (calées par `useAnimatedStyle` sur les valeurs partagées). `clickable` reste faux (pas de gestionnaire de clic natif, on passe par l'action).
- Vérifié : `heavy.sh npx jest iso- village locale` 32 suites, 702 tests verts ; `heavy.sh npx tsc --noEmit` propre ; biome sans erreur ; `heavy.sh npm run deadcode` propre (2 tag hints préexistants).

## Tour 4 (qa, L3-T07a tour 2 : les touches n'arrivaient pas à la carte)
- **Cause** : le test de collision de RNGH sur Android (`GestureHandlerOrchestrator.traverseWithPointerEvents`, vu dans `node_modules`) parcourt les vues du dessus vers le dessous et, pour une vue `pointerEvents` auto sans geste, appelle `shouldHandlerlessViewBecomeTouchTarget` : une feuille (un dégradé) ou une vue à fond qui contient le point devient la cible du toucher, et la carte dessous ne reçoit rien. Dans le hero de `VillageScene`, après le tableau de la carte viennent deux `LinearGradient` (scrim du haut, scrim du bas = 62 % de la hauteur du hero) sans `pointerEvents`, puis le bloc titre (`village-title`, absolu, pleine largeur) et le cameo de villageois (bande pleine largeur, `z={900}`). La démo n'a rien au-dessus de la carte, d'où son bon fonctionnement. Les glissés n'ayant jamais atteint le pan, le verrou de défilement du tour 3 ne se posait jamais, d'où la page qui défilait ; le tap n'atteignait pas non plus la carte.
- **Correction** : `pointerEvents="none"` sur les deux dégradés ; `pointerEvents="box-none"` sur le bloc titre du hero chargé (le blason garde son appui) et sur la bande du cameo (`components/chorus/VillagerCameo.tsx`, hors de ma liste, une ligne : seule sa zone `villager-zone` prend les touches). Les braises avaient déjà `none`.
- **Preuve** : `__tests__/village-scene.test.tsx`, carte iso allumée, parcourt les enfants du hero après celui qui contient la carte et exige `none` ou `box-none` pour chacun ; il était rouge sur le titre (puis sur les dégradés avant correction).
- **Repli `Gesture.Native()`** : pas fait, parce que rien ne prouve que le ScrollView gagne encore une fois les touches livrées à la carte ; le verrou dès le premier toucher (tour 3) est en place. Si qa voit encore la page défiler une fois la carte atteinte, c'est le prochain pas (`blocksExternalGesture` sur un `ScrollView` RNGH), à mesurer d'abord.
- Vérifié : `heavy.sh npx jest iso- village locale villager` 32 suites, 703 tests verts ; `heavy.sh npx tsc --noEmit` propre ; biome sans erreur ; `heavy.sh npm run deadcode` propre (2 tag hints préexistants). Non vérifié sur appareil : qa, glissé et tap sur un bâtiment en mode Village.
